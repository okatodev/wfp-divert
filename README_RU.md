
# Селективный прокси-ретранслятор на базе WFP (Windows)

[Read in English (README.md) ->](README.md)

Легковесная высокопроизводительная фоновая утилита на C++17, предназначенная для избирательного перенаправления TCP/UDP-трафика определенных Windows-приложений через локальный SOCKS5-прокси.

Проект разработан для решения проблем с задержками и блокировками голосовой связи в таких приложениях, как Discord (голосовые вызовы WebRTC/RTC) и Telegram, с использованием модели маршрутизации на базе Windows Filtering Platform (WFP).

---

## Ключевые возможности

- **Ультра-легковесность:** написана на чистом нативном C++17 без тяжелых внешних зависимостей, обеспечивая минимальное потребление ресурсов процессора и оперативной памяти.
- **Активное управление ресурсами:** фоновый поток периодически (каждые 10 секунд) очищает неактивные UDP-сессии, закрывая сокеты и завершая их потоки после 60 секунд отсутствия активности (защита от утечек ОЗУ и системных дескрипторов).
- **Оптимизация кэша сессий:** поиск процесса (PID) выполняется ровно один раз при инициализации нового UDP-порта. Последующие пакеты маршрутизируются мгновенно через быструю хэш-таблицу в памяти, исключая ресурсоемкие системные запросы через IP Helper API.
- **Интеграция в системный трей:**
  - Работает полностью скрыто в системном трее (области уведомлений) Windows.
  - Показ и скрытие консоли логов по клику из контекстного меню трея.
  - Программная блокировка кнопки закрытия консоли («X») для предотвращения случайного завершения процесса пользователем.
  - Динамическая перезагрузка файла конфигурации «на лету» без перезапуска приложения.

## Как это устроено изнутри

```text
 [Программа (например, Discord)] 
       │
       ├──► TCP трафик  ──► Системный прокси ──► SOCKS5 (v2rayN) ──► VPN/VPS
       │
       └──► UDP (Голос) ──► Драйвер WinDivert ──► SOCKS5 (UDP Assoc) ──► VPN/VPS
```

1. **TCP-соединение:** Прокси-клиент (например, v2rayN) устанавливает системный прокси Windows. Discord (приложение на базе Electron/Chromium) автоматически подхватывает его и отправляет весь TCP-трафик (текст, картинки, веб-сокеты шлюза) напрямую в прокси.
2. **UDP-перехват:** При подключении к голосовому каналу Discord инициирует WebRTC-соединение по UDP. Обычные системные прокси не поддерживают маршрутизацию UDP, поэтому драйвер (`WinDivert64.sys`) перехватывает исходящие UDP-кадры.
3. **Сопоставление с процессом:** Сетевой движок анализирует исходящий порт, сканирует системные таблицы сетевых подключений через `GetExtendedUdpTable` и связывает порт с PID и именем процесса (например, `discord.exe`).
4. **Инкапсуляция в прокси:** Если имя процесса совпадает с черным списком, движок удаляет оригинальный исходящий пакет, упаковывает его полезную нагрузку в SOCKS5-заголовок (UDP Associate) и пересылает локальному прокси-клиенту.
5. **Впрыск ответов в систему:** Специальный фоновый поток принимает зашифрованные ответы от прокси, снимает SOCKS5-обертку, воссоздает легитимный входящий IP/UDP-кадр с указанием оригинального индекса физической сетевой карты (`IfIdx`) и впрыскивает его обратно в сетевой стек, делая его видимым для приложения.

## Настройка конфигурации (`config.json`)

Программа считывает параметры из файла `config.json`. Пример файла поставляется вместе со сборкой под именем `config.example.json`:

```json
{
  "proxy_host": "127.0.0.1",
  "proxy_port": 10808,
  "intercept_tcp": false,
  "intercept_udp": true,
  "udp_session_timeout_sec": 60,
  "blacklist": [
    "discord.exe",
    "telegram.exe"
  ]
}
```

### Описание параметров

* **`proxy_host`** (строка): IP-адрес вашего локального VPN-клиента (обычно `127.0.0.1` для v2rayN/Nekoray).
* **`proxy_port`** (число): SOCKS5/Mixed-порт вашего клиента. Как правило, `10808` для v2rayN, `2080` для Nekoray или `7890` для Clash.
* **`intercept_tcp`** (логический): Рекомендуется установить в `false` (гибридная схема). В этом режиме за TCP-трафик отвечает функция системного прокси вашего VPN-клиента, разгружая процессор.
* **`intercept_udp`** (логический): Рекомендуется установить в `true`. Включает перехват UDP голосовых вызовов для перенаправления их в прокси-туннель.
* **`udp_session_timeout_sec`** (число): Время простоя в секундах, по истечении которого неактивная UDP-сессия и её поток безопасно закрываются, освобождая память.
* **`blacklist`** (массив строк): Имена процессов для проксирования в **нижнем регистре** и обязательно с расширением `.exe` (например, `"discord.exe"`).

## Компиляция

Для сборки проекта на Windows требуется наличие CMake и компилятора MSVC/Clang (например, из Visual Studio Build Tools).

1. Создайте папку сборки `build`:
   ```powershell
   mkdir build
   cd build
   ```
2. Сгенерируйте конфигурационные файлы и скомпилируйте проект:
   ```powershell
   cmake ..
   cmake --build . --config Release
   ```
   *Примечание: При успешной компиляции CMake автоматически скопирует библиотеки `WinDivert.dll`, драйвер `WinDivert64.sys` (или 32-bit) и файл шаблона `config.example.json` в выходную папку к исполняемому файлу.*

## Запуск приложения

1. Запустите ваш прокси-клиент (например, v2rayN) и переведите параметр **System Proxy** (Системный прокси) в состояние **"Set system proxy"** (иконка в трее загорится красным). Это обеспечит проксирование TCP-трафика.
2. Создайте файл `config.json` в папке с программой (при самом первом запуске утилита автоматически скопирует его из файла шаблона `config.example.json` в этой же папке).
3. Нажмите правой кнопкой мыши по `wfp_divert.exe` и выберите **«Запуск от имени Администратора»** (необходимо для загрузки драйвера WinDivert в ядро).
4. Программа свернется в трей. Нажав правой кнопкой мыши по иконке у часов, вы сможете:
    - **Show/Hide Console Logs** — открыть или скрыть окно консоли с логами подключений.
    - **Edit Config** — мгновенно открыть файл `config.json` в Блокноте.
    - **Reload Config** — применить любые изменения настроек на лету без перезапуска приложения.
    - **Exit** — остановить перехват, безопасно выгрузить драйвер из ядра и выйти.
