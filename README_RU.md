
# Селективный прокси-ретранслятор на базе WFP (Windows)

[Read in English (README.md) ->](README.md)

Легковесная высокопроизводительная фоновая утилита на C++17, предназначенная для избирательного перенаправления TCP- и UDP-трафика определенных Windows-приложений, хостнеймов, IP-диапазонов и регионов GeoIP через локальный SOCKS5-прокси.

Проект разработан для решения проблем с задержками и блокировками голосовой связи в Discord (голосовые вызовы WebRTC/RTC), Telegram и в целом для любых подобных случаев.

---

## Ключевые возможности

- **Полная прозрачность (No System Proxy):** Утилита работает на уровне сетевых пакетов ядра. Больше не требуется включать системный прокси Windows в VPN-клиентах — программа сама перехватывает TCP и UDP на лету.
- **Двойной NAT (Address Reflection):** Инновационный метод перенаправления TCP-трафика. Программа подменяет IP-адреса отправителя и получателя, преобразуя исходящее соединение во входящее на локальный порт. Это обходит жесткие политики безопасности Windows (Strong Host Model) и предотвращает блокировки брандмауэра без использования сложных петлевых интерфейсов.
- **Обход защищенных PPL-процессов:** Получение ID процессов и их имен через снимки системы `CreateToolhelp32Snapshot` вместо `OpenProcess`. Это позволяет утилите видеть и перенаправлять трафик защищенных процессов (таких как драйверы античитов или системные службы), к которым закрыт доступ даже учетной записи Администратора.
- **Гибкая маршрутизация на основе конфигурации:** Поддержка четырех независимых типов перенаправления трафика: по именам исполняемых файлов (`apps`), по разрешенным доменным именам (`hostnames`), по конкретным IP-диапазонам (`ips` с использованием подсетей CIDR) и по географическим регионам (`geoip` с использованием файлов блоков CIDR).
- **Динамический резолвинг хостнеймов:** Автоматически сопоставляет настроенные домены с их активными IP-адресами при запуске. Перехватывает и проксирует только TCP-трафик, направленный на эти конкретные IP, позволяя остальному трафику проходить в обход SOCKS5-туннеля.
- **Активное управление ресурсами:** Фоновый поток периодически очищает неактивные UDP-сессии, закрывая сокеты и завершая их потоки после тайм-аута (защита от утечек ОЗУ и системных дескрипторов).

## Как это устроено изнутри

```text
 [Программа (Discord и др.)] 
       │
       ├──► TCP (Авторизация/API) ──► Драйвер WinDivert (Double NAT) ──► SOCKS5 (v2rayN) ──► VPN/VPS
       │
       └──► UDP (Голос/WebRTC)    ──► Драйвер WinDivert (UDP Assoc)  ──► SOCKS5 (v2rayN) ──► VPN/VPS
```

1. **TCP-перехват:** Приложение инициирует TCP-соединение. Драйвер (`WinDivert64.sys`) перехватывает его, сохраняет оригинальные адреса в NAT-таблице под ключом исходного порта клиента, выполняет зеркалирование IP и направляет пакет локальному TCP-слушателю. Локальный слушатель принимает соединение, запрашивает у NAT-таблицы реальный адрес назначения и транслирует данные через SOCKS5.
2. **UDP-перехват:** Голосовые UDP-кадры WebRTC перехватываются, упаковываются в SOCKS5-заголовок (UDP Associate) и пересылаются прокси-клиенту.
3. **Впрыск ответов в систему:** Специальный фоновый поток принимает ответы от прокси, снимает SOCKS5-обертку, воссоздает легитимный входящий IP/UDP (или TCP) кадр с указанием оригинального индекса физической сетевой карты (`IfIdx`) и отправляет его в сетевой стек.

## Настройка конфигурации (`config.json`)

Пример файла поставляется вместе со сборкой под именем `config.example.json`:

```json
{
  "proxy_host": "127.0.0.1",
  "proxy_port": 10808,
  "intercept_tcp": true,
  "intercept_udp": true,
  "udp_session_timeout_sec": 60,
  "apps": [
    "discord.exe",
    "telegram.exe",
    "update.exe"
  ],
  "hostnames": [
    "example.com"
  ],
  "ips": [
    "1.1.1.1/32"
  ],
  "geoip": [
    "ru"
  ]
}
```

### Описание параметров

* **`proxy_host`** (строка): IP-адрес вашего локального VPN-клиента (обычно `127.0.0.1` для v2rayN/Nekoray).
* **`proxy_port`** (число): SOCKS5/Mixed-порт вашего клиента. Как правило, `10808` для v2rayN или `2080` для Nekoray.
* **`intercept_tcp`** (логический): Рекомендуется установить в `true`. Включает перехват TCP-соединений драйвером на уровне ядра.
* **`intercept_udp`** (логический): Рекомендуется установить в `true`. Включает перехват UDP голосовых вызовов для перенаправления их в прокси-туннель.
* **`udp_session_timeout_sec`** (число): Время простоя в секундах, по истечении которого неактивная UDP-сессия закрывается, освобождая память.
* **`apps`** (массив строк): Имена процессов для точечного проксирования в **нижнем регистре** и обязательно с расширением `.exe`.
* **`hostnames`** (массив строк): Хостнеймы для автоматического разрешения (резолвинга) при старте и точечного перенаправления.
* **`ips`** (массив строк): Конкретные IP-адреса или подсети CIDR для точечного перенаправления.
* **`geoip`** (массив строк): Коды стран в нижнем регистре для загрузки соответствующих подсетей (например, `"geoip_ru.txt"`) и точечного перенаправления.

## Компиляция

Для сборки проекта на Windows требуется наличие CMake и компилятора MSVC/Clang (например, из Visual Studio Build Tools).

1. Создайте папку сборки `build`:
   ```powershell
   mkdir build
   cd build
   ```
2. Сгенерируйте конфигурационные файлы и скомпилируйте проект:
   ```powershell
   cmake ..
   cmake --build . --config Release
   ```
   *Примечание: CMake автоматически скопирует необходимые библиотеки `WinDivert.dll`, драйвер `WinDivert64.sys` (или 32-bit) и файл шаблона `config.example.json` в выходную папку к исполняемому файлу.*

## Запуск приложения

1. Запустите ваш прокси-клиент (например, v2rayN) и убедитесь, что его SOCKS5-порт активен. **System Proxy включать не нужно** — оставьте его в режиме "Clear" (выключен).
2. Создайте файл `config.json` в папке с программой (при самом первом запуске утилита автоматически скопирует его из файла шаблона `config.example.json`).
3. Запустите `wfp_divert.exe` **от имени Администратора** (необходимо для загрузки драйвера WinDivert в ядро).
4. Программа свернется в трей. Нажав правой кнопкой мыши по иконке у часов, вы сможете управлять консолью логов, редактировать и мгновенно перезагружать конфиг без перезапуска утилиты.
